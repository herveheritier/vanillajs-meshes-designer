# Project knowledge

This file gives Freebuff context about this project: goals, commands, conventions, and gotchas. See `README.md` for the full user-facing docs (UI legend, shortcut table, file formats).

## What this is

**Vanilla-JS 2D mesh editor** — draw points, build triangles, save/load scenes as JSON or a custom « meshes » text format. **Zero dependencies, zero build step, zero framework.** Single page app served as static files.

The whole UI is one HTML page driving a `<canvas>`; HTML/CSS/JS are not transpiled.

## Quickstart

- **Setup:** none for the app itself (zero deps, no transpile). Dev tooling only: `npm ci` once (devDependency `playwright-core` for the smoke tests; `node_modules` is gitignored).
- **Dev:** `python3 test_server.py` from the project root → serves on `http://localhost:8000/`, then open `main.html`. The script does a real bind-check (port + connect-back probe) and exits with an error if the port is taken.
- **Test:** `npm run check` — `node --check` on all `.js`/`.mjs` + the 16 browser smoke suites (auto-starts/stops the dev server). See « Dev tooling & CI » below.
- **Lint:** none.
- **Build (optional):** `npm run build:portable` → single-file offline `meshes-portable.html` (Option A of `PORTABILITE.md`); `npm run check:portable` validates it (rebuild + static checks + `file://` browser test); `npm run check:artifact` tests the CI-published artifact (downloads the latest `meshes-portable` from the last successful `master` run via `gh` + `unzip`, same `file://` walk — `--local <file>` for a local file without CI prerequisites). See « Dev tooling & CI » below.
- **Headless import test:** `http://localhost:8000/main.html?autoimport=<base64-urlsafe-text>` triggers an auto-import of a meshes-formatted string (no file picker needed).

## Architecture

App: one HTML page driving **16 ES modules** (see the `main.html` script tags, topological order) + one Python dev server, plus assets. Dev tooling lives in `scripts/` (never shipped). Key files:

| File | Rôle |
|---|---|
| `main.html` | Layout, CSS (toolbar, HUD, modales), declares the toolbar buttons + help modal + log overlay (`#messageBoard` with drag handle + SE resize grip). Mounts the 16 JS modules. |
| `main.js` | App logic: state (`ctx`, `shapes`, selection, zoom, pan, undo/redo), mouse/keyboard events, drawing, persistence, import/export. |
| `draw.js` | Pure render primitives (points, lines, triangles, axes, grid). All coords go through `modelToScreen()`. |
| `convert.js` | Parser: meshes-format text ↔ multi-shape JSON scene. Reads files via `FileReader` (this is why HTTP serving is mandatory). |
| `test_server.py` | Threaded `http.server` on port 8000 with EADDRINUSE-diagnostics. |
| `assets/` | `barre_boutons.png` (toolbar screenshot), `meshes-sample`, `mesh-1785093938339.json`, `alphabet2` (legacy example). `assets/favicon.svg` is the only asset referenced by the app (`<link rel="icon">`). |
| `scripts/` | Dev tooling only (never shipped): `check.sh` (orchestrates `npm run check`), the 8 `smoke-*.mjs` suites + `smoke_lib.mjs` harness, and the portable toolchain `build-portable.mjs` + `check-portable.mjs` + `check-artifact.mjs` + the shared `portable-browser-test.mjs`. See « Dev tooling & CI » below. |

Data flow: `main.js` owns app state → calls render primitives in `draw.js` (post-transformation via `modelToScreen`) → user input updates state → main persists via `localStorage`.

## Conventions

- **No build / no transpile / no bundler.** Edits + browser reload = iteration. No HMR. Exception: the optional portable build (`npm run build:portable`) concatenates the modules into one HTML — it never modifies the sources.
- **Y axis inverted.** `modelToScreen` flips Y so larger `model.y` renders higher on canvas (math-style). Mind this when touching pan or rotation math.
- **`ctx` shape:** `{ center: {x,y}, viewCenter: {x,y}, zoomLevel: number }`. `center` is pixel position of model origin on canvas (in **CSS pixels**, never bitmap pixels); `viewCenter` is which model point is centered; `zoomLevel` is a multiplier (clamp `[0.1, 10]`).
- **HiDPI:** the canvas bitmap is sized in **physical pixels** (`board.width = round(cssW × devicePixelRatio)`, boot + resize in main.js) for crisp rendering on retina displays, but ALL internal coordinates (mouse, hit-testing, `center`, `modelToScreen`) stay in **CSS pixels**. The CSS→physical conversion happens at two boundaries only: bitmap sizing in main.js, and a `setTransform(dpr,…)` applied in draw.js (`drawBoard` on the visible ctx, `renderSceneToOffscreen` on the offscreen). Never multiply CSS-px values by dpr in logic; use `getDevicePixelRatio()` (exported from draw.js) only where the bitmap size is set. See DESIGN.md §2.7.1.
- **SVG icons in the toolbar are inline** (`stroke="currentColor"`, 14×14). Button labels hidden visually — the verb lives in `title=` and in the action modal only.
- **Comments are concise French *why*-notes**, not prose (convention appliquée depuis août 2026 : ~3 800 → ~1 200 lignes de commentaires). Règle d'équilibre : garder les bannières de sections (`// ===== ... =====`), les commentaires *pourquoi* courts (≤ 2-3 lignes) sur la logique non évidente (invariants, regressions, deferred patches, §DESIGN), supprimer le reste — les longues dissertations vivent dans DESIGN.md, pas dans le code. Ne jamais documenter le *what* (le code le dit).
- **LocalStorage keys** (all share `meshesDesigner.` namespace):
  - `meshesDesigner.consoleVisible` — bool
  - `meshesDesigner.consoleFrame` — JSON `{left,top,width,height}` in px for the log-overlay frame
  - `meshesDesigner.undo` — JSON `{ scene, historyStack, redoStack }` where `scene` is the exact `serializeState()` string written to `meshesDesigner.scene` at the same moment (fingerprint guard at boot)
  - `meshesDesigner.circleSegments` — int, nombre de côtés du cercle (préférence de session restaurée au boot, réglée à la molette en mode cercle)
  - `meshesDesigner.mergeDropRadius` — int, rayon en px écran de la fusion par déplacement (2e fonction de #mergePoints) : réglé à la molette sur le bouton quand le mode est armé, bornes 8–64 (défaut 20), restauré au boot par `restoreMergeDropRadius` (viewport.js), hors wire format. Le VERROU du mode (2e clic quand il est armé, `state.mergeOnDropLocked` — cadenas sur le bouton, le mode survit aux fusions réussies pour enchaîner) est transitoire comme `mergeOnDropActive` : jamais persisté, cycle bouton armé → verrouillé → désarmé, cf. DESIGN.md §7.11
  - `meshesDesigner.colorPalette` — JSON array of hex `#rrggbb` strings (the fill is always derived from `(bg, colorAlpha)` via `triangleFillFromBg`; legacy keys storing `{bg}`/`{bg, alpha}` objects or plain strings are still read — per-swatch alpha is ignored, opacity is global). Editable/enrichable palette restored at boot by `restoreColorPalette` (editor.js), rewritten on every mutation. Preference: never marks the scene dirty, never serialized in exported files.
  - `meshesDesigner.colorAlpha` — float [0,1] working opacity of the `#colorAlpha` slider, the SINGLE opacity applied to every triangle paint (swatch click picks the color, opacity stays the user's). Persisted ONLY on manual slider drags (`persistColorAlpha`); swatch clicks / Escape / Reset / Défauts never overwrite the preference, so the user's last manual setting survives reloads and applies to painting (restored at boot inside `restoreColorPalette`, BEFORE the palette — its fills are derived from it). Same preference status: never marks the scene dirty, never serialized.
  - `meshesDesigner.savedScenes` — JSON array of scene names (« emplacements », évolution enregistrement scène) : list of the scenes already saved, most recent first, deduped, capped at `MAX_SAVED_SCENES = 20`. Written by `recordSavedSceneName` (io.js) after every successful `saveMesh(name)`; read by `getSavedSceneNames` to build the save dialog (`#saveModal`, modals.js) which is positioned on the previous emplacement (names[0]). Preference: never marks the scene dirty, never serialized in exported files.
  - (scene + zoom + grid keys persisted too — search `localStorage` in `main.js` for the full list)
- **`#messageLog`** is the scrollable log region inside `#messageBoard`. Mutations go through it, never through `#messageBoard.innerText` (would destroy the drag handle / clear button).
- **Console overlay minimums:** `CONSOLE_MIN_WIDTH=80`, `CONSOLE_MIN_HEIGHT=30` — resize handler clamps to these.
- **Internal clipboard (cut/copy/paste):** `state.clipboard = { points, tris, offset }` — session-only, never persisted (like preview). `copySelection` / `cutSelection` / `pasteClipboard` live in editor.js and capture the active shape's `selectedPoints` + the triangles **fully contained** in the selection (fills preserved, tris re-indexed relative to the copied point list). Paste always targets the **active shape** (coords are absolute) and shifts by `GRID_STEP / 2` per paste (cumulative via `clipboard.offset`) so repeated pastes cascade away from the source; the pasted copy becomes the selection. Buttons `#copy`/`#cut`/`#paste` (toolbar selection group, disabled-state synced by `updateClipboardButtons` called from `updateSelectionHud`) mirror the same functions as Ctrl+C/X/V — the keyboard handler guards on `typing` so Ctrl+V never hijacks native paste inside modal inputs. Both cut and paste are one undo step each (`replaceShapePatch`). Not `navigator.clipboard` (internal format + fragile under `file://`).
- **Single editing mode:** the project exposes one `state.editingMode === 'edition'` since the construction + selection modes were merged into edition's fluent contract. The toolbar `#editMode` button + `E` shortcut were removed; `EDITING_MODES = ['edition']` and the silent `restoreEditingMode` in `viewport.js` are kept for backwards-compatible localStorage reads only — there is no toggle UI to persist anymore.
- **Mode d'affichage « toutes couleurs » en édition (évolution « bouton pour choisir le mode d'affichage », cf. DESIGN.md §7.18):** `state.showAllFills` (bool) = mode d'affichage PUR — TOUS les plans rendus remplis de leurs couleurs de triangles PENDANT l'édition (les inactifs gardent leurs lignes pointillées + points atténués mais sont remplis via le 3e paramètre `forceFill` de `drawShape` — règle de couleur inchangée `t.fill` ou défaut). Branche `showAllFills` dans `drawShapes` (dessinée après la preview plans, avant le rendu standard) : plans INACTIFS dans l'ordre du tableau (z-order entre eux préservé), plan ACTIF dessiné EN DERNIER (par-dessus) — il garde son rendu actif complet et reste la cible d'édition visible même quand un plan postérieur le chevauche (remplissage opaque ; à la différence de la preview plans où l'ordre strict du tableau prime). S'applique aussi en preview simple (drawShapes appelé) — bouton masqué par la chrome ; pas en preview plans (`return` avant). UI: bouton `#showAllFills` (groupe Canvas ops, juste après `#preview`), cycle standard → toutes couleurs → standard par `toggleAllFills` (viewport.js), PAS de raccourci clavier, état `.all-fills-active` + `aria-pressed` par `updateAllFillsButton` (hud.js, même langage que `#fps.fps-active`). Préférence de vue persistée `meshesDesigner.showAllFills` (`ALL_FILLS_STORAGE_KEY`), restaurée au boot par `restoreAllFills`, jamais dirty ni serialisée (comme le réticule). Chrome masquée en preview par les `:has()` du groupe (le bouton disparaît avec la preview). Couvert par `scripts/smoke-allfills.mjs` (18e suite).
- **Preview 3-state cycle (evolution bouton prévisualiser, cf. DESIGN.md §2.6):** `state.previewMode` = any preview, `state.previewPlans` = 2nd state (all shapes rendered as filled plans in **array order** — shape n = plan n, drawn in `drawShapes` with `isActive=true` for every shape). The `#preview` button and `P` cycle off → preview → plans → off (`togglePreview`); `Escape`, left-click on the canvas and `Ctrl+S` exit **directly** from either state (`exitPreview` — never `togglePreview`, which would cycle to plans instead of exiting). Both states share the same `body.preview-mode` chrome-masking; in preview the toolbar is stripped to the single floating `#preview` button (CSS `:has()` group selectors in main.html) so click-cycling stays possible, with `.preview-active` (green) / `.preview-plans` (amber + ring inset + `#previewText` « plans ») button states. Neither state is persisted (same policy as before).
- **Kiosque de sélection des plans (evolution « mode de sélection du plan actif avec simulation 3D », cf. DESIGN.md §7.16):** `state.kioskMode` (transient, never persisted, mutually exclusive with preview — `toggleKiosk` calls `exitPreview` first, and `Alt+K` works even in preview). Each plan becomes a tilted « card » around a virtual vertical axis (cover-flow): `draw.js:computeKioskLayout` computes the shared layout for render AND click hit-test — per card `dx = i - focus`, `tilt = clamp(dx · KIOSK_TILT_RAD_PER_STEP, ±KIOSK_MAX_TILT_RAD)` (45°/card — `KIOSK_TILT_RAD_PER_STEP = π/4` —, cap ~66°), gaussian `scale` (floor `KIOSK_MIN_SCALE = 0.4`), distant cards raised (`KIOSK_MAX_PARALLAX_Y = 18` px) `kioskFocus()` = a CONTINUOUS linear focus `t·(n-1)` from the pointer abscissa (`t = clamp(x/w, 0, 1)`, canvas edges → first/last plan) — the pointer drives the tilt and highlights one plan at a time (full opacity; others dimmed to `KIOSK_DIM_MIN_ALPHA = 0.3`), a dashed green vertical guide in `renderTransient` marks the pointer axis. `drawKiosk` renders cards in increasing `|dx|` order so the front plan overlaps its neighbors (NO fake-3D edge band — flat cards, the dark side band was removed per user request, EVOLUTIONS); card geometry redrawn from model space via the inverse `modelToScreen` transform (zoom 1, canvas coords). **Card faces use a true PERSPECTIVE projection** (`projectKioskPoint`: local point `(u, v) ∈ [-1, 1]²` rotated `tilt` around the central vertical axis then projected from `KIOSK_PERSPECTIVE_D = 2.5` half-widths: `s = D/(D - u·sin(tilt))`) — the edge approaching the viewer is magnified, the opposite edge shrinks, vertical edges stay vertical (trapezoid, the 45°-tilt look), replacing the flat orthographic `scale(cos tilt, 1)` squash. Plan triangles are projected vertex-by-vertex (perspective is non-affine). NO card frame nor focus ring: the highlighted plan is distinguished only by its plain green « Plan n » text (no badge, BIG `KIOSK_LABEL_FONT = bold 18px`, centered on the projected footprint mid) under the magnified near edge's bottom, plus full opacity (others dimmed). Plan-to-plan transition is a PROGRESSIVE CROSS-DISSOLVE (« fondu enchaîné »): within the |dx| ≤ 1 window, opacity interpolates LINEARLY between the focus (1) and the neighbor's resting level `KIOSK_NEIGHBOR_ALPHA = 0.45` — the outgoing plan actually fades out while the incoming fades in (previously the neighbor stayed at ~0.8, so the switch was carried only by the name/stroke = abrupt); beyond |dx| = 1 the exponential curve (`KIOSK_DIM_MIN_ALPHA = 0.3` + `(KIOSK_NEIGHBOR_ALPHA - min)·exp(-(|dx|-1)/KIOSK_DIM_FALLOFF = 3)`) continues, continuous at |dx| = 1 (`prom = max(0, 1-|dx|)`, `alpha = prom + (1-prom)·rest`); the name is drawn as a CROSS-FADE (alpha = prom) on the two cards adjacent to the focus — the old name fades out while the new one fades in. `cardFootprint` stays the shared render/layout contract (projected u = ±1 edges — anti-clip recentering matches the drawn face exactly; `cardBand` was removed with the edge band). `computeKioskLayout` RECENTERS each card on its slot (the MIDDLE of its projected footprint, not its geometry center which the perspective asymmetry shifts — without it the steeply-tilted extreme cards overflow the screen on the near-edge side; spacing max tightened to `KIOSK_CARD_SPACING_RATIO = 0.35`). Cards are sized to FIT THE SCREEN in BOTH dimensions: `cardDims` caps the width at `cssBoardW × KIOSK_CARD_W_RATIO = 0.55 × scale` (a very elongated plan — aspect capped at 2.8 — would otherwise produce a card wider than the canvas: the fit only protects the geometry INSIDE the card, not the card itself; the height is reduced accordingly to keep the aspect), and `computeKioskLayout` CLAMPS each card inside the screen after recentering (a slot can leave the canvas when the focus is near an edge). Inputs (main.js mousedown on board): left-click → `kioskSelectedIndex(x)` = **the click ALWAYS selects the plan put forward (the focus)**, computed from the click abscissa with the SAME linear rule as the display (`kioskFocusAt`, shared with `kioskFocus`) — no independent footprint hit-test, so the selected plan is always the one shown frontmost even when the pointer is not over its card (margins, gaps): a click can never select a previous/next plan (regression of the former depth-order footprint hit-test `kioskCardIndexAt` + its nearest-center fallback; smoke: 9-plan clicks at 0.375×width → 4/9, at 0.09×width left margin → 2/9) → `goToShape(idx)` + `exitKiosk()` = **select + immediate exit** (user decision); right-click = cancel, middle consumed (no pan); `Escape` exits without change. All editing inputs are cut in kiosk: `updateMouseHover` (editor.js guard `previewMode || kioskMode`), wheel (viewport.js guard — no zoom), pointer only drives tilt via `resolveMouseMoveOnBoard` (kiosk branch: `lastMousePos` + `requestDraw`). UI: `#kiosk` button (shape-nav group, greyed when `state.shapes.length <= 1` via `updateShapeHud`), `Alt+K` shortcut (main.js, guards typing/AltGr `!e.ctrlKey`/`!e.repeat`), control in viewport.js (`toggleKiosk`/`exitKiosk`/`applyKioskMode` with defensive gesture reset like `applyPreviewMode`/`updateKioskButton`/`wireKioskControl` — dedicated wiring, no `wireButton` duplicate). Chrome masked via `body.kiosk-mode` (CSS `:has()` group selectors, only the floating `#kiosk` button remains — but the `#actionComment` toast STAYS visible, unlike preview). Post-action HUD: `showActionComment` on enter (hover guide) and on exit (« ◀ ▶ pour naviguer… Alt+↑/↓ pour l'ordre »). Covered by `scripts/smoke-kiosk.mjs` (17th suite).
- **Mouse buttons:** `e.button === 0` is the canonical left-click gate used everywhere; middle-click on the canvas = pan; `getModifierState('AltGraph')` OR `(ctrlKey && altKey)` = AltGr detection (because AltGr is browser-inconsistent).
- **Contextual HUD comment toast (évolution « message prospectif », cf. DESIGN.md §7.15):** `#actionComment` (main.html, absolute bottom-left above the HUD stack `#coords` → `#zoomDisplay` → `#fpsDisplay`) is **PROSPECTIVE and hover-driven** — it never reports what was done, it says what the user CAN do now and how. Two sources with a priority hierarchy computed in `editor.js:updateHoverComment` → `computeHoverComment` (called from `updateMouseHover` after the `nearest*` computation, behind the hover-signature guard, and from the circle/star/annulus/shape branch): (1) construction modes (phase guides: « 1er clic gauche : pose le centre… » / « 2e clic gauche : valide… »), (2) partial-triangle construction (« poser le 2e/3e sommet »), (3) brushMode (« Clic gauche pour peindre ce triangle… »), (4) element hover in the SAME resolution order as the click (processMouseUpSelection): triangle (triangle mode) > segment (segment mode) > point (« sélectionner ce sommet — clic droit pour le déplacer ») > segment in vertex mode (« **Clic gauche pour créer un nouveau triangle à partir de ce segment** » — the founding example, deliberately « clic gauche » = the real gesture), (5) empty zone: a running post-action finishes its 3 s (`isActionCommentActive()`), else a generic message (« poser le 1er point » on empty scene / « Survolez un segment… » on a closed shape). Hover messages PERSIST while hovering (no timer); `showHoverComment` (hud.js) has a dedup guard (same text + visible + source 'hover' = no DOM rewrite per mousemove) and increments `actionCommentToken` to invalidate any pending post-action timer. `showActionComment(text)` = post-action ~3 s (module-level timer, `clearTimeout` before re-arm — no flicker; text cleared after the `ACTION_COMMENT_FADE = 350` ms fade so no ghost content). The token/source mechanism (`actionCommentSource` = 'hover' | 'action') ensures a post-action timer never removes a hover message that replaced it. Post-action call sites (all import `showActionComment` from hud.js — no import cycle, hud.js only reads `state`): editor.js (addPoint step messages, deleteSelectedPoint/Segment/Triangle, copySelection/cutSelection/pasteClipboard, alignOrDistribute, rotateSelectedPoints at the wheel-debounce commit, circle/star/annulus/shape creation, paintTriangleAtCursor), merge.js (applyMergeToSelection, covers both classic + drop merge), shapes.js (moveShapeUp/Down via moveShape, addShape), history.js (undo/redo), io.js (saveMesh, applyImport merge/replace, resetAll). Hidden in preview (`body.preview-mode #actionComment`), `aria-live="polite"`. Timers live at module level (UI side effects, never persisted).
- **Align/distribute (évolution « boutons pour forcer l'alignement et la répartition des points sélectionnés », cf. DESIGN.md §7.14):** `alignSelectedPointsX/Y` + `distributeSelectedPointsX/Y` (editor.js, shared core `alignOrDistribute`) operate on the active shape's `selectedPoints`. Align = all selected points take the X (or Y) of the **first** selected point (the anchor, other coord kept — vector-editor convention); distribute = even spacing along the axis between the two extreme points (which stay put, `pos_i = min + (max-min)·i/(n-1)`). Each action is **one undo entry** (`replaceShapePatch` before/after — only coords change, tris indices stay valid, fills survive). Guards: align needs ≥ 2 selected points, distribute ≥ 3 (buttons greyed accordingly by `updateAlignPanelButtons` in hud.js, synced via `updateSelectionHud`). UI: `#align` toolbar button (selection group) toggles the `#alignPanel` popover (same pattern as `#shapesPanel`: positioned under the button, closes on Escape / outside click / re-click, stays OPEN after an action to chain align X then align Y), ring-inset state via `updateAlignButton`. Shortcuts Alt+←/→ = align X/Y, Alt+Shift+←/→ = distribute X/Y (main.js, guards typing/preview/AltGr via `!e.ctrlKey`/`!e.repeat`). State flag `alignPanelOpen` (transient, never persisted).
- **Shape order (évolution « boutons pour gérer l'ordre des formes »):** the `state.shapes` array order IS the plan order — in the plans preview, `drawShapes` renders shapes in array order, shape n = plan n, highest index drawn last (on top). `moveShapeUp`/`moveShapeDown` (shapes.js) move the **active** shape ±1 index; UP = index+1 (1/3 → 2/3, the shape passes ABOVE, label rises), DOWN = index-1. Both are one undo entry each: a new `shapeMove` patch kind `{from, to}` in history.js (~16 B, applicator splices both directions) + an adjacent `activeShapeIndexPatch` so undo/redo restore order AND active index. Buttons `#moveShapeUp`/`#moveShapeDown` (shape-nav group) are greyed at the bounds via `updateShapeHud` (first shape: down disabled, last: up disabled); `Alt+ArrowUp`/`Alt+ArrowDown` in main.js call the same functions (guards: `typing`, preview, AltGr excluded via `!e.ctrlKey`, `!e.repeat`).
- **Insertion d'un plan avant/après (évolution « ajouter un nouveau plan en l'intercalant avant/après le plan courant », cf. DESIGN.md §7.17):** `addShape(position)` (shapes.js, défaut `'after'`) insère le nouveau plan vide RELATIF au plan courant — `'before'` = index `activeShapeIndex` (le plan courant recule d'un rang), sinon `activeShapeIndex + 1` — et le rend actif. Le bouton `#newShape` (groupe shape-nav) câble le clic gauche → `addShape('before')` (listener `click`, garde `e.button !== 0`) et le clic droit → `addShape('after')` via un listener `contextmenu` dédié avec `preventDefault` (le listener global du document ne protège que le board) ; le `title` du bouton porte le geste complet (aria-label dérivé par `updateAccessibilityLabels`). Historique : mêmes patches delta que l'ancien append (`shapeArrayPatch(newIndex, null, newShape)` + `activeShapeIndexPatch(fromIndex, newIndex)`, `from === to` dans le cas before) — **`saveState` est appelé APRÈS le splice** (contrat history.js §8.5) : l'ancien pattern saveState-avant ne valait que pour l'append (l'inverse `splice(index=length, 1)` était un no-op), avec l'insertion relative il retirait un plan réel du clone (undo corrompu sur petites scènes ≤ ~4 pts/tris) ; activation par `activateShape`, helper extrait de `goToShape` — l'insertion AVANT garde le même index numérique, la garde `newIndex === state.activeShapeIndex` de `goToShape` (no-op de navigation) sauterait le nettoyage transitoire. Guidance post-action positionnée (« Plan vide AVANT/APRÈS le plan courant — cliquez pour poser le 1er point »). ## Gotchas

- **Must serve via HTTP, not `file://`.** `convert.js` uses `FileReader` and the import drag-drop, both blocked by browser under `file://`. The README and the help modal both say so.
- **localStorage is sticky across reloads.** Scene, grid step, zoom, *and* console visibility + frame position persist. Clear it from devtools between tests for a clean slate.
- **`temp.json` is gitignored** — it's the browser's auto-download dump from `downloadMesh`; not part of the repo.
- **`main.js` mutates `messageBoard.innerText`** heavily (one of the slowest DOM APIs). Acceptable here because the log is small, but avoid the pattern elsewhere.
- **No unit tests / no lint.** The automated guards are `npm run check` (syntax + 18 smoke suites) and `npm run check:portable` (portable build + `file://` test), wired into CI. Treat visual verification in a browser as the primary test loop for new interactions.
- **Encoding:** meshes format uses `;` between vertices and `,` between coords; no locale, no units — raw floats.
- **AltGr rotation pivot tracks cursor** in model space; still anchored to the cursor at the first tick of the gesture, but recomputed if the cursor moves mid-gesture (search `pivotScreen` in `main.js`).
- **Undo/redo history** in `historyStack` / `redoStack` (capped at `MAX_HISTORY = 50`, oldest evicted). Call `updateUndoRedoHud()` after any mutation you make on those stacks — it syncs the `#undoCount` pill and the `disabled` attribute on the toolbar buttons. Keyboard shortcuts `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` and the toolbar `#undo` / `#redo` buttons share the same `undo()` / `redo()` functions (single source of truth). Both stacks persist to `meshesDesigner.undo` and are restored at boot by `loadState()` → `restoreUndoHistory()` (fingerprint `scene` must match the restored scene, else entries are discarded). Reinit points (memory + persisted): `resetAll()` and import REPLACE in `applyImport`; import MERGE KEEPS the stacks (`markUndoPersistDirty()` refreshes the fingerprint after the append). Whenever you mutate the stacks in a new code path, call `markUndoPersistDirty()` so the next `persistState()` rewrites the undo key.
